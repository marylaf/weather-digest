# Weather Digest

Консольная утилита для ежедневной сводки погоды. По списку городов запрашивает геокодинг и прогноз Open-Meteo, печатает таблицу минимума/максимума температуры и осадков на несколько дней и сохраняет JSON-отчёты в каталог `reports`. Города обрабатываются независимо: ошибка по одному не останавливает остальные.

## Требования к окружению

- Node.js 20 или новее
- npm
- доступ в интернет к API Open-Meteo (геокодинг и прогноз)
- Docker и Docker Compose — только для запуска в контейнере

## Установка

```bash
git clone https://github.com/marylaf/weather-digest.git
cd weather-digest
cp .env.example .env
npm install
```

Файл `.env` подхватывает Docker Compose. Локальный `npm start` читает переменные из окружения процесса; параметры `--city`, `--days` и `--no-cache` можно передать и флагами CLI.

## Переменные окружения

| Переменная      | Описание                                                                | По умолчанию                                     |
| --------------- | ----------------------------------------------------------------------- | ------------------------------------------------ |
| `CITY`          | Города через запятую. Обязательна, если не передан `--city`             | —                                                |
| `DAYS`          | Число дней прогноза, целое от 1 до 7                                    | `3`                                              |
| `NO_CACHE`      | Не читать кэш отчётов: `true`/`1`/`yes`/`on` или `false`/`0`/`no`/`off` | `false`                                          |
| `GEOCODING_URL` | Endpoint геокодинга Open-Meteo                                          | `https://geocoding-api.open-meteo.com/v1/search` |
| `FORECAST_URL`  | Endpoint прогноза Open-Meteo                                            | `https://api.open-meteo.com/v1/forecast`         |
| `TIMEOUT_MS`    | Таймаут HTTP-запросов в миллисекундах                                   | `5000`                                           |
| `REPORTS_DIR`   | Каталог для JSON-отчётов                                                | `./reports`                                      |
| `UNITS`         | Единицы: `metric` (°C, мм) или `imperial` (°F, in)                      | `metric`                                         |

Флаги CLI имеют приоритет над `CITY`, `DAYS` и `NO_CACHE`.

## Запуск

### Параметры CLI

| Параметр     | Описание                                    | Обязательный | Значение по умолчанию |
| ------------ | ------------------------------------------- | ------------ | --------------------- |
| `--city`     | Города через запятую                        | да\*         | —                     |
| `--days`     | Число дней прогноза, целое от 1 до 7        | нет          | `3`                   |
| `--no-cache` | Не читать сохранённые отчёты, запросить API | нет          | выключен              |

\*Либо `--city`, либо переменная `CITY`.

### Команды

```bash
# Флаги CLI
npm start -- --city "Москва,Казань,Сочи" --days 3 --no-cache

# Только обязательный параметр (days = 3, кэш включён)
npm start -- --city "Москва"

# Через переменные окружения
CITY=Москва,Казань DAYS=3 NO_CACHE=true npm start

# Смешанный запуск: города из CLI, остальное из окружения
DAYS=5 UNITS=imperial npm start -- --city "London,Paris"

# Режим разработки с перезапуском при изменениях
npm run dev -- --city "Москва" --days 3

# Сборка TypeScript и запуск скомпилированного файла
npm run build
node dist/index.js --city "Москва" --days 3

# Docker Compose (читает .env)
docker compose run --rm weather-digest
```

Дополнительно:

```bash
npm test            # автотесты API на Jest + Supertest
npm run typecheck   # проверка типов
npm run lint        # ESLint и Prettier
npm run web         # просмотр сохранённых отчётов в браузере
```

## Ошибки и коды завершения

| Код | Когда                                                                       |
| --- | --------------------------------------------------------------------------- |
| `0` | Все города обработаны успешно                                               |
| `1` | Ошибка аргументов/окружения **или** хотя бы один город завершился с ошибкой |

Фатальные ошибки (процесс сразу завершается с кодом `1`, печатается сообщение и справка `Usage`):

| Сообщение                                                             | Причина                                    |
| --------------------------------------------------------------------- | ------------------------------------------ |
| `Missing required argument: --city or CITY`                           | Не задан список городов                    |
| `Invalid argument: --days or DAYS must be an integer between 1 and 7` | `DAYS` / `--days` не целое в диапазоне 1–7 |
| `Invalid environment variable: NO_CACHE must be a boolean`            | Некорректное значение `NO_CACHE`           |
| `Invalid environment variable: UNITS must be "metric" or "imperial"`  | Некорректное значение `UNITS`              |
| ошибка `parseArgs`                                                    | Неизвестный флаг (режим `strict`)          |

Ошибки по городу (остальные города продолжают обрабатываться; процесс завершается с кодом `1`, если была хотя бы одна такая ошибка):

| Тип                       | Сообщение в консоли                                                               | Когда                           |
| ------------------------- | --------------------------------------------------------------------------------- | ------------------------------- |
| `CityNotFoundError`       | `Ошибка для города "<город>": город не найден`                                    | Геокодинг не вернул результатов |
| `HttpStatusError`         | `Open-Meteo вернул ошибку <код>` или `Open-Meteo временно недоступен: HTTP <код>` | HTTP 4xx / 5xx                  |
| `TimeoutError`            | `Превышено время ожидания запроса (<TIMEOUT_MS> мс)`                              | Запрос дольше `TIMEOUT_MS`      |
| `NetworkError`            | `Не удалось подключиться к Open-Meteo`                                            | Сбой сети                       |
| `InvalidJsonError`        | `Open-Meteo вернул некорректный JSON`                                             | Ответ не JSON                   |
| `InvalidApiResponseError` | `Неожиданная структура ответа Open-Meteo (...)`                                   | JSON есть, но схема не совпала  |

Повреждённый или отсутствующий файл кэша не считается ошибкой: отчёт запрашивается у API заново.

## Структура проекта

```text
weather-digest/
├── src/
│   ├── index.ts              # точка входа CLI
│   ├── api/                  # HTTP-клиент, геокодинг и прогноз Open-Meteo
│   ├── config/               # разбор аргументов, env, константы, единицы
│   ├── errors/               # иерархия ошибок приложения
│   ├── format/               # табличный вывод в консоль
│   ├── services/             # оркестрация запроса и кэша
│   ├── storage/              # чтение/запись JSON-отчётов
│   ├── types/                # типы CLI, конфига, погоды
│   └── utils/
├── tests/                    # автотесты API (Jest + Supertest)
├── web/                      # просмотр сохранённых отчётов (Vite + React)
├── docs/postman/             # коллекция запросов к Open-Meteo
├── reports/                  # кэш отчётов (создаётся при запуске)
├── Dockerfile
├── docker-compose.yml
├── .env.example
└── package.json
```
